    Reading Numbers Off Charts: What the Benchmark Found

    A plain-language tour of the figure-extraction benchmark -- what works, what breaks, and what to build next. With the real test charts and the real code.

    The one-sentence version. Pulling the average out of a chart is basically solved -- every method gets it right to about half a percent. Pulling the error bars (the spread) is where everything breaks, and the spread is the number a meta-analysis leans on most. That gap is small, specific, and measurable -- which is exactly what makes it a good target for a machine-learning tool.

    The question we tested

    A meta-analysis combines many studies. A huge fraction of the numbers it needs -- group averages, standard deviations, sample sizes -- live only as ink in a published chart, never written in the text. So someone (or something) has to read the numbers back off the picture. The question: how accurately can that be done, and where does it fail?

    The trick: let the computer grade itself

    To grade a chart-reader you need the true answers with total certainty. So we run it backwards. The statistics program R invents a dataset, computes everything about it (means, SDs, sample sizes), and then draws the chart from those exact numbers. Because the chart was built from data R computed, the "right answers" aren't guessed off the picture -- they are what the picture was made from. R even hands us the exact pixel location of every bar top and every error-bar cap. That is a flawless answer key.

    # benchmark/r/rgt.R -- R exports the TRUE pixel position of every drawn mark
library(grid); library(ggplot2)
p <- ggplot(df, aes(group, mean)) + geom_col() +
       geom_errorbar(aes(ymin = mean - sd, ymax = mean + sd))
b <- ggplot_build(p)                       # R's computed panel ranges
loc <- grid::deviceLoc(unit(x_npc,"npc"), unit(y_npc,"npc"))  # data -> inches -> PIXELS
# every bar-top and error-cap pixel becomes ground truth this way (verified vs the
# drawn ink to a median of 0.44 pixels).

    We independently checked R's answer key by detecting the actual drawn ink in each image and comparing: they agree to 0.44 pixels on average. The answer key is trustworthy.

    Finding 1: the height is easy, the error bar is hard

    Turning a pixel into a value is exact arithmetic once the axes are calibrated -- so if you place the points perfectly, you recover the numbers perfectly (we measured 0.00% error). The whole problem is where you place the points. And placing them splits cleanly in two:

    # benchmark/harness -- the two channels we score
mean_hat = bar_top_value                       # central tendency
disp_hat = abs(cap_value - bar_top_value)      # the error-bar half-height
if dispersion_type == "SEM": sd_hat = disp_hat * sqrt(n)   # SEM -> SD
central_err    = 100 * abs(mean_hat - true_mean) / true_mean
dispersion_err = 100 * abs(sd_hat  - true_sd)  / true_sd    # <-- the load-bearing number

    Finding 2: even a perfect human can't click precisely enough

    Here is the result that changes the argument. We simulated a perfect human -- someone who clicks exactly where they mean to, but with the tiny, unavoidable wobble of a real mouse, about one pixel. That one pixel barely touches the average, but it throws the spread off badly:

    Why does one pixel matter so much for the spread but not the mean?

    The consequence. A b% error in the cap becomes roughly a 2b% error in the variance, which mis-weights a study by about the square root of its sample size. So the imprecision isn't a "bad user" problem -- it is baked into asking a human to hand-click short marks. The most trusted digitizing tool, WebPlotDigitizer, is validated by studies showing humans agree with each other closely -- but those studies never isolate the error-bar reading and assume good clicks. Our benchmark shows good human clicking still carries real error on exactly the quantity that matters.

    Finding 3: it holds up on real journal figures

    Synthetic charts could be a special case, so we ran the real test: we took actual figures from the articles in a completed dissertation meta-analysis (where the true numbers were hand-coded by a human expert), read them automatically, and compared.

    • The pattern transfers. On real panels the average was again nearly free (~0.5%), and the spread was again the failure (3.7% typical, 18% worst -- worst on the shortest caps).
    • The conclusion reproduces. When we fed the automatically-read numbers through the same statistics as the hand-coded ones, the pooled effect size came out +0.475 versus the hand-coded +0.487 -- essentially identical, with no study flipping direction. The machine reached the same scientific answer.
    • A concrete real-world snag. In real figures, significance asterisks sit right on top of the error caps; a one-shot read confuses them and misses the cap by 20-36% until the panel is zoomed 2-3x. That is precisely the kind of mistake a specialized detector is built to remove.

    Finding 4: the model already knows what kind of chart it is looking at

    Before a tool can read a chart's numbers, it has to know what kind of chart it is (a bar? a box plot? a forest plot?). We built a corpus of 80 charts -- 18 chart types drawn with 12 different R graphing libraries, each in a plain version and a deliberately cluttered "dense" version (packed with legends, significance stars, annotations, panel labels).

    A few of the 80 test charts -- 18 types across 12 R libraries.

    Result: 100% correct (80/80), and the cluttered "dense" charts were just as easy as the plain ones. This is good news that relocates the problem: figuring out what a chart is is not the bottleneck. The error is all downstream, in reading the spread and in real-figure messiness -- not in recognizing the chart.

    Can this classifier improve figure & sub-panel detection? (your question)

    Short answer: not directly, but yes as a component -- and there is a bigger free win hiding in how we built it. The key is that classification and detection are different jobs:

    • Classification takes a cropped chart and says "this is a box plot." That is what scored 100%.
    • Detection takes a whole PDF page and says "there is a figure here, and it has panels A, B, C at these locations." That is finding where things are -- a different skill the classifier doesn't do on its own.

    But the classifier helps detection in two concrete ways:

    1. As a verifier / filter. After Figure Extractor proposes candidate figure or panel regions, run the classifier on each. Real chart? Keep it. Classifies as "unknown" or with low confidence? It's probably caption text, a schematic, or a bad crop -- drop it. A confident classifier is a good gatekeeper for noisy detections.
    2. As a boundary score for sub-panel splitting. A correctly-cropped single panel classifies confidently as one chart type; a bad split (half of one chart plus half of its neighbor) classifies as "unknown" or with low confidence. So you can search for the right panel boundaries by choosing the cuts that make each piece classify most confidently.
    The bigger opportunity. The R engine that draws these charts already knows the exact pixel box of every panel in a multi-panel figure (that is how it exports ground truth). So we can generate, for free, a labeled training/eval set of "figure image -> panel bounding boxes" -- exactly what you need to train a real sub-panel detector and drop it into Figure Extractor. Same idea as the specialist landmark detector, but aimed at layout instead of data points. Caveat: the 100% is on clean, isolated single charts; detecting panels on real, text-heavy PDF pages is a harder input, so it needs its own detection model -- but we already have the ground-truth generator to build and score it.

    What it all means

    • The math is exact; only the point-picking is noisy. So accuracy is entirely a perception problem, and perception is improvable.
    • Humans are the weak link on the spread. Even careful clicking can't read short error caps precisely -- which makes "a machine can be more precise than a human here" a real, defensible claim, and "take the human out of the digitizing loop" a serious proposal (the human's job moves to confirming the type of error bar -- SD vs SEM -- which is written in the caption, not measured off pixels).
    • Knowing the chart type is solved; reading the spread is not. That is the precise target for a specialized machine-learning tool.
    • It works on real figures -- the automated read reproduced a real meta-analysis's conclusion -- but this is still an agreement test against human coding, not yet proof that a trained model beats a general agent on messy real figures.
